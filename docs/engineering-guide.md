# 微光助手工程规范

这份文档汇总已确认且持续适用的项目约定。实现和命令以当前源码与 CI 为准。对话中的单次排查、临时方案和已撤回的方案不作为后续任务。

## 产品与代码

- 中文产品名为「微光助手」，英文名为 Microlight，中文副标题为「桌面 AI 智能体」。模块路径和 GitHub 仓库统一使用 `github.com/ggdream/microlight`。新增代码、配置键、产物、文档和界面使用 Microlight 或 microlight，历史标识仅用于读取已有安装数据。
- 根目录只保留一个 Go 文件 `main.go`，负责入口和资源嵌入。应用启动放在 `internal/app`，页面按职责放在 `internal/pages/<页面>`，较大的独立组件可继续拆包。应用内部能力放在 `internal/` 的对应职责包。可独立复用的库放在 `pkg/`，维护和发布脚本放在 `scripts/` 或 `.github/scripts/`。
- 按职责拆 Go 包，用简洁的包名和文件名。明显属于同一功能的实现和测试放在一起。平台差异使用 Go 文件名后缀和构建约束表达。使用仓库已有的组件、数据结构和流程。
- 资源放在根目录 `assets/`，中英文文案源文件和 MyGo 生成的访问器放在 `assets/locales/`。改界面文案时同步更新简体中文和英文源字典，并用 MyGo 生成访问器。中文文案采用明确、专业的产品用语。
- 项目使用纯 Go 和 MyGo 原生 UI，测试、交叉编译和打包统一使用 `CGO_ENABLED=0`。运行时可使用平台原生能力。仓库脚本沿用 Go 或 shell，避免引入 Python 工具链或把外部项目混入构建。
- 移动交互优化优先使用现有 Go API、purego 或现有桥接；这些方式无法完成的能力先保留限制，不为此另写 Swift/Kotlin 原生插件。
- 对外 README 用英文，面向开源用户，突出纯 Go、零 cgo、原生 UI、跨平台编译和响应性能。快速开始包括 `go install github.com/ggdream/microlight@latest` 和安装后的启动命令。Windows 如在双击时弹出控制台，可在 README 的说明里给出 `-ldflags="-H=windowsgui"`。维护和实现细节放在 `docs/`。许可证为 Apache 2.0。 [README](../README.md) · [LICENSE](../LICENSE)

## 设置与桌面交互

- 全应用采用黑色主色的 Material 3 视觉体系，浅色中性表面；颜色、圆角、字阶、阴影和控件状态由 `pkg/material3` 统一提供。主操作用 FilledButton，普通操作用 ElevatedButton 或 TonalButton，取消、工具栏及次操作用 TextButton；卡片和弹层以底色与轻阴影分层，不使用周边描边。内容分隔线、表格和单选/复选指示器仍可保留必要的线条。菜单图标悬停保持原色，一行只绘制一层轻量状态反馈，避免父行与子按钮叠加背景。新增界面同时接入 `pkg/viewport`。详见 [Material 3 组件约定](material3.md)。
- 通用设置更改后立即生效并持久化。模型配置统一通过页底「保存设置」提交。用户有未保存的模型变更时，切换到其他设置页或返回对话应先弹出确认。配置导入确认后、导出启动后显示居中转圈的模态 Loading，遮挡并阻止其他区域的鼠标、触摸及键盘交互；导入处理及导出编码、保存放到后台，结束后撤掉遮罩，用 MyGo Toast 反馈成功或失败，取消选择、确认或保存不弹结果。
- 配置迁移覆盖所有已保存的应用设置和相关密钥，使用带格式版本的 JSON，默认文件名为 `microlight-config.settings`。桌面导入默认筛选 `.settings`，并提供「全部文件」以兼容旧 JSON。Windows/Linux 使用 MyGo 筛选列表，macOS 的纯 Go/purego 适配提供独立切换，避免 MyGo 合并筛选项导致默认过滤失效。macOS 原生面板将不匹配文件置灰；移动端及 Web 的筛选呈现由系统/浏览器决定，不能宣称与桌面切换完全一致。导入仍按文件内容校验，不以扩展名替代验证；确认后用一次事务更新设置。会话、草稿、附件、归档和磁盘技能文件各自保留。
- 模型设置支持多个命名供应商，每个供应商有独立的连接、模型和生成参数。供应商使用可选 Chip，未选中为浅灰底、选中为黑底白字加勾选，悬停时加深并平滑展开删除区域，删除需二次确认。Chip 支持拖拽排序，落点可见，拖动不切换当前供应商；排序随「保存设置」持久化，放弃修改恢复原顺序，Esc 取消当前拖动。选择项和当前配置区域应有明确的视觉层级，动态供应商名用胶囊等独立样式标识。
- 同一供应商下所有模型都使用同一行式输入，主题化单选器标记默认模型，单选器、输入框和删除控件竖直居中。添加模型直接添加可编辑行，最后统一保存。连接测试由用户选择具体模型，使用当前表单值。聊天顶部切换供应商，输入区切换已配置的模型。
- 内置浏览器默认以设置中的运行方式为准（初始为前台）。用户明确指定前台或后台时，工具按本轮要求执行，不更改已保存的设置。同一回复内的后续浏览器操作沿用已启动的模式；切换模式需要重新导航。
- MCP 设置使用「超时时间」，默认「不限制」，由用户按服务设置。传输类型在服务列表中用胶囊显示，地址可以截断，操作区应保持可辨识、可点击。配置的默认值、暂停等待与连接取消仍由对应流程处理。
- 「个性化」类文本设置统一使用「自定义指令」。它用于指定回复和协作偏好，作为应用内置系统指令的一部分追加。用户自定义内容和应用的工作区、工具、权限及协议规则各自保留原有职责。
- 全局快捷键以实际键帽显示，唤起主窗口后焦点进入聊天输入框。原生与 Web 通知的范围由一个下拉项控制，包含关闭选项。「发送测试通知」直接触发系统通知，方便在应用当前可见时检查横幅。Web 使用浏览器通知 API，权限只由用户选择通知范围或发送测试通知时申请；后台回复不弹权限请求，拒绝权限时提示浏览器网站设置。原生通知继续使用 MyGo。
- 「关于」页合并版本和检查更新，左侧为「版本」，右侧为可选中的版本号与无描边的更新操作。仓库地址使用 GitHub 图标、仓库名和外链提示。默认两行采用一致的高度和左右布局。手动检查更新通过弹窗反馈结果，版本行不追加结果文字。发现新版时弹窗明确显示最新版本号，并区分「下载安装包」与「查看发布说明」：前者由默认浏览器直接下载当前系统和架构的安装包，后者打开对应版本的 GitHub Release；没有对应安装包的平台仅提供发布页，不能猜测下载链接。检查请求沿用应用代理配置。
- 桌面功能优先使用 MyGo 对应能力。Secrets 集成暂缓，桌宠已从产品范围移除。Windows 和 Linux 托盘使用应用彩色图标，macOS 菜单栏使用由系统着色的模板图标。

## 输入、滚动与聊天内容

- 使用 MyGo 提供的逻辑窗口尺寸，通过 `pkg/viewport` 切换布局。小于 600 点显示单栏和限宽历史抽屉，600 点起可显示侧栏，900 点起可并排显示文件预览。横向距离和纵向距离分别以 390 点和 760 点为参考缩放。字号用独立的宽度曲线，窗口仅变矮时字号保持稳定。页面通过 X、Y、Text 和 Target 应用尺寸策略，通用控件与 Markdown 使用适配后的窗口主题。紧凑布局保留常用触控目标和文字的可用尺寸，优先减少留白、换行或滚动。尺寸计算使用扣除安全区后的可用空间。普通内容由 MyGo 自动避让系统栏和键盘，抽屉及遮罩的背景延伸到系统栏下方。平台判断只用于系统能力。验收覆盖桌面拖窄和手机竖屏。
- 技能设置支持下拉重新扫描，历史会话可长按打开操作菜单。
- 紧凑布局的普通居中弹窗默认宽度为可用窗口的 80%，最大 360 点，并受两侧安全留白限制。这是微光对确认、编辑与会话信息的统一设计取舍，不是平台规定；不把弹窗拉伸至接近全屏，也不缩小字号来容纳内容。参考 [Flutter Material 外侧留白](https://api.flutter.dev/flutter/material/Dialog/insetPadding.html) 与 [Cupertino 弹窗实现](https://github.com/flutter/flutter/blob/master/packages/flutter/lib/src/cupertino/dialog.dart)。图片全屏预览、系统分享和选择器按各自的交互处理。
- 移动端视觉验收按页面和状态逐项截图：空白首页、输入与键盘、历史抽屉及菜单、各设置页顶部与底部、下拉选项、编辑和确认弹窗、审批与澄清、排队消息、交付物、文件和图片预览、统计明细。先按手机使用方式整理信息层级，再校准间距，避免仅把桌面元素等比缩小。确认、编辑、会话信息等普通弹窗在手机上仍居中展示，保留安全区和键盘避让；底部面板只用于选择器、分享等相应交互。长内容滚动时操作仍可见。输入区按实际排版高度适应自动折行，技能目录等辅助信息默认折叠。截图使用独立测试配置，区分模拟器实拍和原生渲染器的尺寸用例，不把后者当作设备验收。
- iOS 与 Android 使用 MyGo 系统文件选择器和保存副本。移动端会话可使用应用私有工作区。桌面托盘、全局快捷键、桌面更新、外部命令、本机 MCP 子进程与 Chromium 自动化只在桌面启用。HTTP MCP、网页搜索、OCR 和已导入的附件继续使用现有配置和会话审批。
- Web 保持现有 `database/sql`、SQLite SQL 和业务表结构，通过 `pkg/sqliteweb` 桥接独立 Worker 中的 wa-sqlite 与 IndexedDB 分页 VFS；不能改为 localStorage 或定时整库快照。原生平台继续使用原有无 cgo SQLite 驱动，Web 导入通过 `js/wasm` 构建约束隔离。不要自行维护数据库 VFS。Web 正式构建使用仓库脚本以包含同源 Worker 与固定版本资源，验收需覆盖事务回滚、刷新、突然关闭标签页和多标签页写入。浏览器网络遵守 CORS 与浏览器代理设置，不宣称能绕过；不支持的原生能力隐藏并停止注册。详见 [Web 存储与验收](web-storage.md)。
- 网络统一使用 `pkg/proxy`。Android 的系统代理通过 MyGo Kotlin 原生模块读取 `ConnectivityManager.defaultProxy`，由系统 `ProxySelector` 处理 Wi-Fi 手动代理、绕过列表及 PAC；不能回退到 Linux GIO 或环境变量发现。PAC 尚未准备好时返回代理错误。iOS 与 macOS 共用 CFNetwork，读取系统配置并在系统 RunLoop 中执行 PAC。每次请求重新解析路由，以支持运行中切换网络和代理；只按系统明确返回的 DIRECT 路由直连。系统代理验收使用独立模拟器配置和真实模型，核对代理转发日志、手动代理、PAC 分流及绕过规则，结束后恢复网络设置。Windows 的 WinHTTP 与 Linux 的 GIO 实现独立保留，修改移动端时不得覆盖已有 Windows 修复。
- 普通、密码、搜索、多行和 A2UI 表单文本输入使用无阴影的描边样式：默认中性灰细线，悬停加深，聚焦为黑色较粗描边，标签放在框外上方。聊天消息输入区保留独立的表面样式。输入保留对称横向内边距，长文本、遮罩、选区、光标和输入法组合文本应在内容区域内显示，聚焦不改变内容位置。验收需覆盖溢出和光标到末尾的情况。光标颜色使用 `#3e3e3e`，沿用主题配置。 [主题实现](../internal/theme)
- 页面、侧栏、列表、面板等独立滚动区域使用 `pkg/elastic` 的弹性滚动，并对滚动内容应用返回的偏移。输入框、表格和内嵌内容保留原生滚动，滚动条和裁剪区保持在原位。 [弹性滚动实现](../pkg/elastic)
- MyGo 固定到包含连续触摸滚动修复的 `76516b5fda74` 提交，避免惯性滚动期间第二次滑动被吞掉。紧凑尺寸的消息编辑回填并聚焦底部输入框，取消后恢复原草稿与附件；提交仍创建分支。权限与模型选择使用 Go UI 底部面板，桌面尺寸保留弹出菜单。Markdown 的长按拖选尚受 MyGo 现有接口限制，不以纯文本编辑器替换富文本内容。
- 网页读取与本地文件读取分别设限。网页最多读取 5 MiB，提取 HTML 可读文字后最多返回 60 KiB，并明确标记截断；最多跟随 5 次同站跳转，允许同主机 HTTP 升级 HTTPS。跨站跳转返回新地址，由新工具调用沿用审批流程；所有请求保留已配置的 HTTP 传输和代理。
- 复用主题的图标、按键和单选器。弹出菜单使用 `internal/theme` 的 `PopupMenu`、`PopupMenuAt` 或 `PopupContextMenu`。调整交互模式时可先查看同类产品的具体界面，尤其是供应商设置、快捷键录入、服务列表和更新入口。悬停不能造成文字和操作碰撞，窄窗口下应优先保证输入和点击。首页快捷输入使用普通用户常见的生活问题，例如饮食、穿搭、旅游、出行。
- 聊天中的 URL 支持悬停预览卡片，提供站点、可用的标题和摘要，并有明确的打开操作。本地附件悬停只显示完整路径。附件获得焦点时按空格打开系统 Quick Look，右键通过主题菜单调用同一预览操作，草稿附件菜单还提供带图标的移除操作。
- 聊天图片设最大高度，保持比例并完整显示。点击打开大图，大图右上角提供下载图标。右键菜单提供带图标的预览与下载，下载保存原图。
- Android/iOS 图片长按菜单提供带 Fluent 图标的「分享」，使用 `mygo.Share` 分享原图文件。MyGo v0.10.0 的 Share 在桌面返回不支持，因此按平台能力显示入口。窄屏下图片菜单使用「分享、预览、保存」短文案，图标保持一致。分享文件保留在应用私有缓存中，不能在系统面板刚出现时删除，因为目标应用尚未读取文件。
- 不同会话可以并行执行，应用层不设并发会话数量上限。每条会话独立管理运行、停止、排队、澄清和审批。同一会话中的后续发送沿用用户配置的排队或转向行为。
- 聊天顶栏仅在有 Eino 后台任务时显示数量。点开可查看正在执行的命令、进入来源会话或停止任务。继续失败任务时保留已完成的交付物和工具结果，对恢复期间的新增或结果未明的写入、命令和 MCP 操作逐次审批。独立会话与后台命令可并行执行。
- 交付物随回复显示。结构化写入自动登记文件和变更，其他工具生成的本地文件可由 Agent 显式登记。结构化写入按目标校验最近读取的版本。发生冲突时保留当前文件并在回复中显示路径。并行执行的 Shell 命令仅按重叠工作区提示，Shell 的任意文件修改无法逐项归因。
- 后台命令通过 Eino 的进程内运行器启动，沿用微光的工作区和权限检查。任务 ID 使用 UUIDv7，原回复结束后任务可继续运行。应用退出后不能重新连接到这类命令。
- 开启完全访问权限前，用户需勾选说明并点击确认。每次打开弹窗都从未勾选开始，取消或切换会话会清除确认状态。
- 展开的 Shell 操作显示命令与执行内容，附复制图标。网页搜索和浏览器操作只显示摘要。用户澄清通过一张问答卡片与对应的历史记录呈现。思考内容折叠区域依赖模型实际返回的思考数据。Markdown 支持 Mermaid，适合用图表达的流程可优先选择 Mermaid。验证中文标签清晰、边线标签不遮挡、复制保留源码。图节点使用圆角、自然阴影和克制的描边。

- 悬停回复时显示「重新生成」。重新生成历史回复会从该处创建新分支，并保留原对话及后续消息。通用设置的「显示用量统计」默认开启，随配置导入导出。悬停回复或在回复内使用键盘时，底部显示本轮的用量和耗时图标，悬停图标查看明细，移开图标后立即关闭。输入框下方用一行显示会话汇总，每组只显示一个核心指标。桌面悬停查看明细，移开后关闭，触控布局点按查看。用量以供应商返回为准，缺失时明确标记；模型耗时不包含工具执行及等待用户的时间。

## Agent、模型与 A2UI

- 模型调用沿用 Eino 的 `AgenticModel` 和类型化 ADK 会话。协议默认 OpenAI Responses，支持 OpenAI Chat Completions 和 Anthropic Messages。会话审批与工作区约束独立于模型输出、工具结果和项目文档。 [模型与会话实现](../internal/pages/chat)
- 修改全局提示词时保持主题中立。提示词可以说明工具、协议、交互和表达形式。避免针对某一类具体题材、风格或内容增加正向或负向引导。复现问题所用的具体题材留在测试样例内，交互规则用通用表述。
- A2UI 以官方 1.0 协议和 Dart 三个参考包的功能为基准。协议与界面状态放在 `pkg/a2ui`，Agent 提示、目录协商和流式解析放在 `pkg/a2uiagent`，MyGo 原生渲染和交互放在 `pkg/a2uimygo`。三个包都用 Go 实现，宿主集成留在应用内部。功能对齐包括协议、状态、原生渲染、交互回传和应用实际接入。
- 用官方 Schema、Basic Catalog 与用例核对功能，参考 Dart 源码补齐行为。升级官方用例需核对来源提交和覆盖范围。新能力应同时检查实际聊天的入口、恢复与错误行为。仅通过已接入的用例时，验收结论应明确覆盖范围。 [协议用例](../pkg/a2ui/testdata/official) · [Agent 用例](../pkg/a2uiagent/testdata/official) · [渲染用例](../pkg/a2uimygo/testdata/official)
- 点击即回传的选项使用带 `Event` 的 `Button`，事件携带结构化值和可读意图。可编辑的 `ChoicePicker` 绑定数据模型，提交由独立按钮负责。A2UI 表单、普通澄清和权限审批保留各自的执行路径。
- 远程媒体沿用宿主 HTTP 客户端、代理和现有加载策略。视频优先走 MyGo 的系统解码后端，宿主可提供替代解码器。媒体和状态的更改要验证正常聊天路径。

## 本地验证与发版

- 通常先运行无 cgo 全量测试。平台测试使用 `t.TempDir()`、`filepath` 和可移植的路径断言。A2UI 变更同时执行官方用例，并验证应用层回传。GUI 交互变更应在可用的桌面平台验证，区分自动化测试和真机验证。

  ```sh
  CGO_ENABLED=0 go test -mod=readonly ./...
  CGO_ENABLED=0 go test -mod=readonly ./pkg/a2ui ./pkg/a2uiagent ./pkg/a2uimygo -run TestOfficial
  ```

- 需要让用户现场看效果时，macOS 用 MyGo 正式打包并重启当前本地产物。仓库脚本按 `go.mod` 选择 MyGo CLI 版本。常规验收沿用打包重启，单次任务有明确要求时以其为准。产物统一放 `dist/`。 [打包脚本](../scripts/build.sh)

- 移动端调用同版本 MyGo CLI，模拟器构建用 `build -platform ios/simulator`，Android 构建用 `build -platform android`。CLI 会为移动端开启 cgo 并使用 Xcode 或 Android NDK 链接宿主。iPhone 和 iPad 共用 iOS 构建，真机签名需开发团队和描述文件。发布渠道的签名材料通过环境配置。 [MyGo 移动端构建文档](https://github.com/egoist/mygo/blob/v0.10.0/docs/mobile/building.md)

  ```sh
  bash scripts/build.sh -skip-dmg
  ```

- 应用显示版本由 Git 决定，用 MyGo 的 `MYGO_LDFLAGS` 注入。干净的标签提交显示 `vX.Y.Z`，标签后提交显示 `vX.Y.Z-短哈希`，无可达版本标签时显示 `v0.0.0-短哈希`。工作区有暂存、未暂存或未跟踪改动时追加 `+dirty`。CI 正式发版使用对应 Git 标签。通过 `go install` 安装时读取 Go 模块构建信息。
- 普通分支推送和 PR 在 Ubuntu 24.04 跑全量测试。平台文件、构建约束和原生能力入口的改动按路径加跑相关平台。依赖、打包、CI 或共用桌面能力变更跑三平台。手动触发跑三平台测试。打包和 GitHub Release 由版本标签推送触发，并等待三平台测试通过。 [CI 工作流](../.github/workflows/ci.yml) · [平台选择脚本](../.github/scripts/test-platforms.sh)
- iOS 与 Android 的源码、依赖、资源、原生模块或构建脚本改动增加移动端编译打包检查；纯文档改动不额外构建移动端。Android 在 Ubuntu 上构建，iOS 在 Apple Silicon macOS 上构建。CI 不安装或启动应用，不运行模拟器，不截图；交互问题按需要在本地验收。标签发版等待编译打包检查通过，移动端产物随桌面包上传 Release。Android 日常检查和发版统一构建 arm64，通过 `MICROLIGHT_ANDROID_COMPRESS_LIBS=1` 启用原生库压缩，仅发布一个使用固定发布密钥签名的 arm64 APK，文件名不加 debug/release 后缀；标签构建必须通过 Secrets 提供签名材料并校验证书，不上传 AAB；Eino 的 Sonic 依赖不支持 32 位，不能使用默认全 ABI 构建。签名、产物类型与检查边界见 [移动端 CI](mobile-ci.md)。
- 提交消息使用 `feat:`、`fix:`、`perf:`、`chore:`、`docs:` 等前缀。按任务指定范围提交、推送或发版。发版时先确认目标提交的 main CI 通过，再推送 `vX.Y.Z` 标签，等 Release 上传完成后核对三平台产物。
- 安装产物命名统一为 `microlight-vX.Y.Z-platform-arch.xxx`。当前平台组合为 `darwin-amd64` 与 `darwin-arm64` 两个独立 DMG、`windows-amd64` 的 EXE，以及 `linux-amd64` 的 DEB、RPM 和 TAR.GZ。 [发布脚本](../.github/scripts/package-release.sh)
- Web CI 只运行 Go HTTP 服务器测试并编译打包，不安装 Node、Playwright 或浏览器。IndexedDB、事务、刷新恢复、多标签页、正式 UI 输入和通知等浏览器验收仅在本地需要时运行；每次推送与 PR 均构建 Web。Web 发布只提供两个 TAR.GZ：站点根目录静态包，以及包含 Windows amd64、Linux amd64/arm64、macOS amd64/arm64 五个内嵌资源 HTTP 服务器的整合包。入口为 `cmd/webserver/main.go`，生成资源不提交；目录首页、History 回退和缺失资源 404 均需测试。标签发版等待 Web HTTP 服务器测试与构建成功。
